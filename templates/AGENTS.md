# 作業ディレクトリのルール（AIエージェント向け）

このディレクトリ配下の `YYYY-MM-DD-<slug>/`（または `<案件>/YYYY-MM-DD-<slug>/`）は、`workroom` で管理している作業部屋である。
以下の「作業ディレクトリ」は、いま作業している `YYYY-MM-DD-<slug>/` を指す。

## 基本
- 作業は作業ディレクトリ内で完結させる。他の作業ディレクトリは参照してよいが、変更しない。
- 小さなファイルを大量に作らない（クラウドストレージで同期している場合に重くなるため）。
  - `.venv` / `node_modules` を作らない。`uv init` / `uv venv` / `uv add` / `pip install` / `npm install` は使わない。
  - Python は `uv run --with <pkg> script.py`、または PEP 723 のインラインメタデータ付きスクリプトを `uv run script.py` で実行する。
  - 本格的な環境構築が必要になったら、作業を止めて、Git 管理された別の場所へ移すことをユーザーに提案する。
- `git init` しない。
- `.done` は完了マーカー。勝手に作成・削除しない。

## ファイルの置き場所
- 作業ディレクトリ直下に置くのは `README.md` / `AGENTS.md` / `log.md` だけ。他は以下のディレクトリに置く（必要になったら作る）。
  - `log.md`: 調査・作業のログ。セッションごとに `## YYYY-MM-DD HH:mm 〜（エージェント名）` の見出しを付けて追記する。
    試したこと・分かったこと・判断の理由を簡潔に書く。過去の記述は書き換えない。
  - `docs/`: 整理したドキュメント。ログから分かったことのうち、後から読む価値があるものをまとめる。上書き更新してよい。
  - `artifacts/`: 成果物（スクリプト、生成ファイル、最終版の文書など）。
  - `tmp/`: 中間ファイルやダウンロードしたデータなど、後で消してよいもの。
- ファイル名は内容が分かる名前にする（日本語可）。`final2` や `new` のような名前は付けない。

## README.md
- `README.md` はこの作業のサマリー。会話の内容に合わせて随時更新すること。
  - 1行目（`# 〜`）は作業一覧に表示される1行説明。日本語で30字程度。目的がはっきりした時点と、目的が変わった時点で更新する。
  - 本文は「目的」「結論・成果物（`docs/` `artifacts/` の主要ファイルへのリンク）」「未完了のこと・次にやること」だけを短く書く。
  - `- created: ...` の行は消さない。
