# workroom 設計

AI エージェント（Claude Code / Codex など）に、日付付きの「作業部屋」ディレクトリを用意する CLI。
Git 管理するほどでもない調査・作業の場所を、すぐに作れて、すぐに戻れて、あとから探せる状態にする。

- 実行ファイル名は `workroom`。普段打つ関数名は `workroom init <shell> --cmd wk` で `wk` などに変えられる（zoxide の `--cmd` と同じ方式）。
- 参考にしたツール：[tobi/try](https://github.com/tobi/try-cli)、[try-rs](https://github.com/tassiovirginio/try-rs)（UI）、[scry](https://github.com/stephendolan/scry)（エージェント向けという発想）。
  - try 系との違いは、エージェント向けのルール管理、README の1行目を一覧に表示すること、完了マーカー、中身の横断検索、Claude の会話履歴を引き継ぐ import、案件階層。
  - try-rs にある、テーマの切り替え・git clone・worktree は持たない。

## ディレクトリ構成

```
<root>/
├── _workroom/
│   └── AGENTS.md              ルールのテンプレート（部屋を作るときにコピーする）
├── 2026-11-02-fix-bug/         部屋（YYYY-MM-DD-<slug>）
│   ├── README.md               1行目 = 一覧に表示する説明
│   ├── AGENTS.md               ルール（テンプレートのコピー）
│   ├── log.md / docs/ / artifacts/ / tmp/   （エージェントがルールに従って作る）
│   └── .done                   完了マーカー（任意）
└── example/                    案件ディレクトリ（任意）
    ├── _workroom/AGENTS.md     案件ごとの追加ルール（任意）
    └── 2026-11-02-report/
```

- 部屋の名前は `YYYY-MM-DD-<名前>`。名前には日本語・英字（大文字・小文字は入力のまま）・数字・`-`・`_` などを使える。
  - 使えない：`/`（案件との区切りとして解釈する）、`\ : * ? " < > |`、制御文字、空白（全角を含む）、先頭の `-` `.`、末尾の `.`。
  - 入力は前後の空白を削り、途中の空白の並びを `-` 1つにする。
  - 説明（日本語の1行）は README.md の1行目に書く。
- 案件名も同じ規則に加えて、先頭の `_` `.`、`YYYY-MM-DD-…` の形、Windows の予約名（`CON` `NUL` `COM1` など。拡張子付きも）は使えない。
  - 設定 `project_uppercase = true` で、案件名の ASCII 英小文字を大文字にそろえる（`example営業` → `EXAMPLE営業`）。既存のディレクトリ名は変えない。
- `案件/名前` と書くと、案件の下の部屋を指す（`wk new EXAMPLE/調査`、TUI の検索語）。案件は1階層だけ。
- **Claude Code の履歴の名前の衝突を検出する。** Claude Code は会話履歴をパス由来の名前（英数字以外を `-` に置換）で保存するので、`2026-11-03-調査` と `2026-11-03-分析` は同じ名前になる。部屋を作る（import する）ときに、既存のすべての部屋と比べ、ぶつかるなら作らずに案内する。ぶつかる部屋はないが Claude の履歴だけが残っている場合は、作ったうえで警告する。名前が 200 文字を超えると Claude 側の規則が変わるので検査しない。
- 名前の検査は、作業ルートやテンプレートを作る前に行う。
- 配置は `<root>/<部屋>` と `<root>/<案件>/<部屋>` の両方を自動で判別する。`.` や `_` で始まるディレクトリは案件とみなさない。
  - Google Drive for desktop でフォルダを同期すると、ルート直下に `.tmp.drivedownload` / `.tmp.driveupload` が作られる。これらを案件として扱わないことをテストで固定している。
- **Windows で Codex を使う場合、作業ルートは NTFS 上に置く。** Codex の Windows サンドボックスは、起動時に作業ディレクトリへ ACL（サンドボックス用の書き込み権限）を付ける。Google Drive の仮想ドライブ（`G:` など）は ACL に対応していないため `SetSecurityInfo failed: 87` で失敗し、シェルが一切起動しない（`helper_unknown_error: setup refresh had errors`）。クラウドに残したい場合は、NTFS 上のフォルダを Google Drive for desktop などのフォルダ同期でバックアップする。
- 部屋は移動しない。Claude や Codex の会話履歴は絶対パスに紐づくので、移動すると resume できなくなるため。完了は `.done` で表す。

## エージェントのルール（AGENTS.md）

**ルールの全文を各部屋の AGENTS.md にコピーする。**

- Codex は、Git 管理外のディレクトリでは親の AGENTS.md を自動では読まない。`../AGENTS.md` を読むよう案内する方式だと、エージェントが案内に従ってファイルを読めるかどうかに頼ることになる。部屋の AGENTS.md に全文があれば、それだけでルールが届く。
  - 以前、案内方式で「Codex が `../AGENTS.md` を読めなかった」例があった。これは、読み取りの制限ではなく、Codex のシェル自体が起動していなかったことが原因の可能性が高い（下記の Windows の注意）。
- Claude Code は親ディレクトリの AGENTS.md も読み込む。テンプレートを `<root>/AGENTS.md` に置くと、部屋のコピーと二重に読み込まれる。そこで、自動では読まれない `_workroom/AGENTS.md` に置く。
- コピーした内容の1行目に、生成元の識別子を入れる（`<!-- workroom:rules sha256=<本文の sha256>（…） -->`）。本文は BOM なし・改行 LF にそろえる。
  - `workroom rules sync` を実行すると、生成後に手で変更されていない部屋（本文の sha256 が識別子と一致するもの）だけを、最新のテンプレートで更新する。AGENTS.md がない部屋には作る。手で変更された部屋は置き換えず、一覧に出す。`--dry-run` で、書かずに予定だけを表示できる。
  - `rules sync` はテンプレートを自動では作らない。テンプレートがなければ何も書かずにエラーで終わる（作業ルート直下に AGENTS.md があれば、`_workroom/` へ移すよう案内する）。移し忘れたまま実行して、既存のコピーを内蔵の文面で上書きしないため。
- 作業ルート直下に AGENTS.md があると、Claude Code が部屋のコピーと二重に読み込む。自動では移動せず、部屋を作るたびに警告する。
- 案件の部屋には、全体のテンプレートの後ろに、案件のテンプレート（あれば）を連結してコピーする。
- テンプレートの場所は設定 `agent_rules` で変えられる。ファイルがなければ、内蔵の文面（`templates/AGENTS.md`）から作る。
  - 内蔵の文面は、workroom の仕組みに必要なルール（部屋の中で作業する、README の1行目、`.done`、確認事項のコマンド）だけにする。使うツールやファイルの置き方などの流儀は利用者ごとに違うので、利用者が自分のテンプレートに書く。

## シェル連携

実行ファイルは、呼び出し元シェルのカレントディレクトリを変えられない。そこで、ラッパー関数を介して移動する。

1. ラッパーが一時ファイルを作り、`workroom --cwd-file <tmp> <引数...>` を呼ぶ。
2. workroom は、1行目に移動先、2行目に（あれば）移動後に起動するコマンド（`claude` / `codex` のみ）を UTF-8・BOM なしで書き出す。
3. ラッパーがそのファイルを読み、cd してから、必要ならコマンドを起動する。

- TUI の描画と標準出力の取り込みがぶつからず、PowerShell / nushell / bash / zsh で同じ方式で動く（yazi の `--cwd-file` と同じ考え方）。
- `claude` / `codex` を実行ファイル側ではなくシェル側で起動するのは、Windows の npm 製の起動スクリプト（`codex.ps1` / `codex.cmd`）を、シェルの通常の解決順で見つけるため。
- ラッパー関数（`init` の出力）は ASCII だけで書く。PowerShell は外部コマンドの出力を `[Console]::OutputEncoding` で読むため、日本語版 Windows の既定（shift_jis）では UTF-8 の日本語が化け、`Invoke-Expression` が構文エラーになる（`-NoProfile` で確認済み）。
- PowerShell のラッパーは、実行ファイルを `Get-Command -CommandType Application` で探して呼ぶ（関数名を `workroom` にしても自分自身を呼ばないように）。既定の関数名は `wk`。
- nushell 0.100 では、外部コマンドが 0 以外で終わるとエラーになり関数が止まる。一時ファイルを消すため、呼び出しを `try` で囲む。
- nushell の `source` には、解析時点で決まっているパスが必要になる。そのため、`workroom init nu --cmd wk | save -f <file>` で一度ファイルに保存し、config.nu から `source <file>` する（zoxide と同じ方式）。

## コマンド

| コマンド | 動作 |
|---|---|
| `wk` / `wk <検索語>` | TUI ピッカー（検索語を入れた状態で起動） |
| `wk new <名前\|案件/名前> [説明] [-p 案件] [--date D] [-c\|-x]` | 作成して移動する。既にあれば移動のみ。`-c` で claude、`-x` で codex を起動 |
| `wk new -p 案件 [--date D] [-c\|-x]` | 案件に絞った TUI を開く。選んで移動するか、「+ 新規作成」で案件の下に作る |
| `wk ls [検索語] [-a\|-o] [--days N] [--depth N]` | tree 表示。既定は直近 N 日で進行中のもののみ。`-a` で全件、`-o` で直近 N 日より前の未完了のもの |
| `wk grep <pattern> [rg のオプション...]` | 中身の横断検索。rg があれば rg、なければ内蔵の簡易検索 |
| `wk done` / `wk undone [名前]` | 完了マーカーを付ける・外す（名前を省くとカレントの部屋） |
| `wk open [名前]` / `wk root` | ファイラーで開く / ルートへ移動 |
| `wk import <path> [名前] [説明] [--date D] [-p 案件]` | 既存のディレクトリを移行する（下記） |
| `wk rules sync [--dry-run]` | 各部屋の AGENTS.md をテンプレートに合わせて更新する（`--dry-run` で予定だけを表示） |
| `workroom q ask <質問> [--background 文] [--choice 文]... [--recommend 番号] [--origin ID] [--by 名前]` | 質問を起票する。標準出力には ID だけを1行で出す |
| `workroom q pending [--json]` | 未反映の回答と、未回答の件数・ID を表示する |
| `workroom q done <ID> [--upto n] [--to 反映先] [--chat 要旨] [--by 名前]` | 回答を反映した場所と解決を記録する |
| `workroom q withdraw <ID> --reason 理由 [--successor ID] [--by 名前]` | 無効になった質問を取り下げる |
| `workroom q show [--all] [--json]` | 質問と回答を表示する。`--all` で解決済み・取り下げを含める |
| `workroom init <pwsh\|nu\|bash\|zsh> [--cmd 名前]` | ラッパー関数を出力する |
| `workroom config [--init]` | 設定ファイルのパスと内容を表示する（`--init` で雛形を作成） |

- サブコマンド名と一致しない語は検索語になる。サブコマンドと同じ語を検索するときは `wk -- done`。PowerShell は素の `--` を自分で消費するので `wk '--' done` と書く。

## 確認事項（QUESTIONS.jsonl / ANSWERS.jsonl）

ユーザーへの質問を ID 付きで起票し、回答の反映と取り下げを記録する。エージェントのシェルにラッパー関数がない場合もあるため、テンプレートと実行例では `workroom q` と書く。`wk q` でも実行できる。
解析・状態の判定・追記・ロック・採番は `src/questions.rs` にまとめる。将来の成果物ハブもこのモデルを読む。ハブ自体と回答の書き込みはまだ実装しない。

### ファイルとスキーマ

両ファイルは部屋の直下に置く。UTF-8（BOM なし）、改行 LF、1行1オブジェクトの JSON Lines とし、日本語はエスケープしない。
`QUESTIONS.jsonl` は `q ask`・`q done`・`q withdraw` だけが追記する。`ANSWERS.jsonl` は将来ハブだけが追記する。既存行を修正・削除しない。
Markdown を人とプログラムで編集する方式では同時編集や手書きの揺れが起きるため、書き手を分けた JSONL とコマンドを使う。

すべてのイベントには `v`（現在 1）、`type`、`id`、`at` がある。`at` は秒までの RFC 3339、記録した機械のローカルの時差付きで、表示だけに使う。質問側のイベントには任意の `by`（実行したエージェント名）を付けられる。

| type | 必須の項目 | 任意の項目 |
|---|---|---|
| `ask` | `question`（1行） | `background`（複数行可）、`choices`（文字列の配列）、`recommend`（1 から数えた選択肢の番号）、`origin`（元の ID） |
| `done` | `to`（反映先）、`upto`（反映した回答の最大番号。回答なしは 0） | `chat`（会話で受けた回答の要旨） |
| `withdraw` | `reason` | `successor`（後継の ID） |
| `answer`（回答側だけ） | `n`（その ID の回答の通し番号）、`kind`（`answer` / `not_needed`）、`text`、`question`（起票の写し） | 写しには起票の項目と `by`・`asked_at` を含める |

```json
{"v":1,"type":"ask","id":"Q-20261106-01","at":"2026-11-06T10:12:03+09:00","by":"エージェント","question":"出力形式は表でよいか","choices":["表","文章"],"recommend":1}
{"v":1,"type":"done","id":"Q-20261106-01","at":"2026-11-06T15:40:00+09:00","to":"README の条件","upto":0,"chat":"表でよいと会話で回答があった"}
```

将来の回答側の例（テストではこの形式を用意する）:

```json
{"v":1,"type":"answer","id":"Q-20261106-01","n":1,"at":"2026-11-06T14:05:12+09:00","kind":"answer","text":"表でよい。\n根拠も添える。","question":{"question":"出力形式は表でよいか","choices":["表","文章"],"recommend":1,"by":"エージェント","asked_at":"2026-11-06T10:12:03+09:00","origin":null}}
```

`not_needed` はユーザーの「回答不要」。`text` は任意の理由で、空でもよい。回答は同じ ID に何件でも足せ、写しから回答側のファイルだけでも質問と回答を表示できる。将来のハブでは本文を1件 64 KiB までに制限する。

### 状態の判定

次の順番で判定する。`A` はその ID の正しく読めた回答の件数、`R` は `done.upto` の最大値（回答の件数を上限とする）。

1. `withdraw` があれば「取り下げ」。最後の理由と後継を表示し、追加の回答が届いても変わらない。
2. `A > R` なら「回答済み・未反映」。解決後の追加回答や `not_needed` もここに入る。
3. `done` があれば「解決済み」。会話での回答だけで閉じた場合も含む。
4. それ以外は「未回答」。

時計や同期のずれに左右されないよう、日時を判定に使わない。回答の順番はファイル内で ID ごとに数える。`n` が違えば警告し、モデルの `n` は順番に直し、元の値を `recorded_n` に残す（ディスクは直さない）。`upto > A` も警告する。
回答側だけにある ID は「質問なし（写しから表示）」にする。起票のない `done` / `withdraw` は無視する規則のため、その ID への解決・取り下げの記録はエラーにする。`pending` では解決コマンドを案内せず、同期状態の確認を促す。
取り下げた項目の回答は記録として表示し、`pending` には出さない。別ファイル間の前後関係を日時なしには判定できないので、取り下げの後に届いたかどうかは断定しない。

### 読み取りと警告

1行ずつ読み、ファイル先頭の BOM・行末の CR を除き、空行を飛ばす。JSON・UTF-8 の不正、オブジェクトでない行、必須の項目の不足や型の不正、ID の形の不正は、ファイル名・行番号・理由を警告して飛ばす。
知らない `type` とフィールドは警告せず無視する。`v > 1` は行ごとに1つ警告し、読める項目を使う。同じ ID の `ask` は最初を採用して重複を警告する。`ask` のない `done` / `withdraw` は警告して無視する。
1ファイルが 8 MiB を超えたら読まずにエラーにする。末尾の改行がなくても正しい JSON なら読める。次の追記の前には改行を足し、途中で止まった壊れた行とつながない。

案内と警告は標準エラーに出す。`pending`・`show` の Markdown では警告を標準出力の末尾にも出し、JSON では `warnings` 配列に含める。色は付けない。ファイルは修復しない。

### ロックと採番

追記の前に、部屋の中の `.QUESTIONS.jsonl.lock` を `create_new` で排他的に作る。中身はプロセス ID と日時。50 ms ごとに再試行し、5秒でエラーにする。更新日時から30秒を超えたロックは停止したプロセスが残したものとして削除する。成功・失敗のどちらでも Drop でロックを消す。
ロックを持ったまま両ファイルを読み直し、存在の確認・採番・`upto` の計算を行う。JSON の行と必要な先頭の改行をまとめ、追記モードで1回の `write_all` で書く。

ID は `Q-YYYYMMDD-NN`。日付は `room::today(settings)`（`day_start_hour` を考慮）。同じ日付の最大の連番に1を足す。2桁から始め、100件目以降は3桁以上になる。壊れた行も、ID が読める範囲で予約する。
部屋にロックを置くのは、部屋だけに書けるエージェントの環境で使うため。`File::lock` は Rust 1.89 以降なので MSRV 1.88 では使わず、依存も増やさない。別の機械が同期フォルダに同時に書く場合は対象外で、重複は読み取り時の警告で検出する。

### 部屋の解決とコマンドの詳細

`--room <名前>` は既存の `room::resolve` の部分一致を使う。省略時は `room::resolve_cwd` で祖先だけをたどり、日付つきの名前で README.md か AGENTS.md があるディレクトリを探す。全部屋を走査しない。
設定が読めれば、作業ルート直下か、隠しディレクトリでない案件の直下だけを認める。設定が読めなければ最も外側の候補を使い、日付の区切りは既定の0時にする。設定が読めるが別のルートを指す場合はエラー。既存の `done`・`open` などの部屋の解決は変えない。
部屋がなければ「部屋の中で実行するか、--room を指定してください」と出す。`--room` には読める設定が必要。

- `ask`：質問の前後の空白を除き、1〜1000文字・改行なしを検査する。`--recommend` は選択肢の範囲内。`--origin` は同じ部屋にある ID。標準出力は採番した ID だけ、標準エラーに未回答の件数を出す。`--by` 省略時は環境変数 `CLAUDECODE` があれば `Claude Code`、それ以外は省略する。
- `pending`：未反映の回答だけを、本文を2文字字下げして表示する。前の反映済みの回答は件数だけ。最後に未回答の件数と ID を出す。解決用の実行例に、出力時点の最後の回答の `--upto` を入れる。`--room` で読んだ場合は同じ部屋の指定も付ける（Windows は PowerShell、それ以外は POSIX シェル向けの引用）。対応がなければ1行、ファイル自体がなければ「確認事項はありません。」。
- `pending --json`：`room`、`pending`（`id`、起票の項目、未反映の `answers`（`n`・`at`・`kind`・`text`）、`reflected_upto`）、`unanswered`（ID）、`warnings`。
- `done`：ID が存在し、取り下げていないこと。`--upto` があれば今の件数と小さい方までを記録する。なければ今の全件を記録し、新しく反映した回答の本文を標準出力に出す。反映済み以下の番号や解決済みの再実行は、`--chat` がなければ追記しない。未回答のまま閉じることはできず、会話で回答を受けたなら `--chat` が必要。`--to` は必須だが、反映対象の回答がすべて `not_needed` なら省略でき、既定は「回答不要」。
- `withdraw`：理由と、指定があれば同じ部屋の後継 ID を記録する。再実行は追記しない。反映済みの場所をすべて、未反映の回答は件数を表示して見直しを促す。聞き直す場合は先に `ask --origin <旧ID>`、次に `withdraw <旧ID> --successor <新ID>`。
- `show`：未回答と未反映の質問・背景・選択肢・回答のすべてを表示する。`--all` では解決済みと取り下げも ID 順に出し、反映先・会話での回答・取り下げの理由・後継も表示する。`--json` は `room`、`questions`（起票・回答・反映・取り下げのイベント、状態、反映済み件数、重複の有無）、`warnings`。

成功は終了コード 0（未反映があっても 0）、実行時エラーは 1、引数の誤りは clap の 2。移動やエージェントの起動は行わず、`--cwd-file` に書かない。

## TUI ピッカー（try-rs を参考に）

```
┌ wk  ~/workroom ──────────────────────────────┐┌ プレビュー ──────────────────┐
│> b                          1/3  最近使った順││# 不具合調査                  │
│> 26-11-02 fix-bug  不具合調査                ││- created: 2026-11-02 19:33   │
│  + 新規作成: b                               ││docs/                         │
│                                              ││  調査まとめ.md               │
│                                              ││3 files · 12.4 KB             │
└──────────────────────────────────────────────┘└──────────────────────────────┘
Enter 移動  ^D 完了  ^O 開く  ^S 並び順  Tab 完了済み  Alt+P 詳細  Esc 終了
```

- `wk` で開く。`wk <検索語>` なら、検索語を入力した状態で開く。標準入力・標準出力が端末でなければ、案内を出して終了コード 2 で終わる。
- 新規作成は「+ 新規作成」の行で `Enter`（専用のキーは設けない。`Ctrl+N` は fzf と同じく選択の移動）。検索語を名前の規則で解釈する（`案件/名前` なら案件の下）。名前にできなければ、行に理由を出し、作らない。
- `wk new -p 案件` で開いたときは、その案件の部屋だけを出し（枠に「案件: …」）、`/` のない検索語は案件の下に作る。
- 一覧の各行：アイコン（任意）、日付（`YY-MM-DD`）、`案件/`slug、README の1行目、完了マーク。
- 完了済みの部屋は、検索語があっても `Tab` を押すまで隠す（隠している件数を表示する）。`wk ls <検索語>` は完了済みも表示するので、扱いが異なる。
- 画面を表示している間は、標準エラーに何も書かない（画面が崩れる）。作成・移動のメッセージと移動先の書き出しは、端末を元に戻してから行う。
- 並び順の既定は**最近使った順**。`Ctrl+S` で「最近使った順 → 作成日順 → 名前順」と切り替える。検索語があるときは一致度の順で、同点ならこの並び順に従う。
- 使用履歴は作業ルートではなく、ローカルの状態ディレクトリ（`<data_local_dir>/workroom/history.json`）に保存する。クラウド同期されたルートに書くと、移動のたびに同期が走るため。履歴にない部屋は、作成日を代わりに使う。
- 検索は slug・案件・説明を対象にしたファジー検索（nucleo-matcher）。
- キー操作：

| キー | 動作 |
|---|---|
| 文字入力 / Backspace / `Ctrl+U` | 検索語の入力 / 1文字削除 / 全消去 |
| `↑↓` / `Ctrl+P` `Ctrl+N` / `Ctrl+K` `Ctrl+J` | 選択の移動 |
| `Enter` | 移動する。「+ 新規作成」の行なら、検索語を名前にして作成する |
| `Ctrl+D` | 完了の切り替え（削除はしない） |
| `Ctrl+O` | ファイラーで開く |
| `Ctrl+S` | 並び順の切り替え |
| `Tab` | 完了済みの表示・非表示 |
| `Alt+P` | プレビューの表示・非表示 |
| `Esc` / `Ctrl+C` | 終了 |

- プレビュー：README の先頭数行、ファイル構成（深さ2）、ファイル数と合計サイズ。
  - サイズはメタデータだけを合計し、中身は読まない（オンデマンド同期のドライブでもダウンロードが発生しない）。
  - 計算は別スレッドで行い、結果はキャッシュする。
- アイコンは Nerd Font を使う。設定 `icons` で有効にする（既定はオフ。使っている端末のフォントが分からないため）。
- Windows の crossterm は、キーを押したときと離したときの両方でイベントを送る。`KeyEventKind::Press` だけを処理すること。

## import

既存のディレクトリを部屋として取り込む。

1. 日付は `--date`、なければ名前の先頭の `YYYY-MM-DD`、それもなければ作成日を使う。名前は引数で指定するか、移行元の名前から作る（空白を `-` にする。大文字・小文字と `_` は保つ）。移行先の Claude の履歴の名前が既存の部屋とぶつかるなら、コピーを始める前にエラーにする。
2. コピーしてファイル数を照合する。README.md と AGENTS.md がなければ作る。
3. Claude Code の `<claude_dir>/projects/<旧パス由来の名前>/` を `<新パス由来の名前>/` にコピーする。jsonl 内の `"cwd":"<旧パス>"` を新しいパスに書き換える（Windows 形式と `/c/...` 形式の両方。後ろが `"` `\` `/` のものだけを対象にする）。元の履歴は残す。
4. 移行元を削除する。

**Claude Code の非公式な内部形式に依存している**ので、形式が変わると動かなくなる可能性がある。README にもその旨を明記する。

## 設定

`$XDG_CONFIG_HOME/workroom/config.toml`、未設定なら `~/.config/workroom/config.toml`（Windows でも同じ）。

```toml
root = '~/workroom'          # 作業ルート
day_start_hour = 0           # 5 にすると 4:59 までは前日の日付で作成する
recent_days = 14             # ls の既定の表示日数
icons = false                # Nerd Font のアイコン
project_uppercase = false    # 案件名の英小文字を大文字にそろえる
exclude = ["node_modules", ".venv", "__pycache__", ".git"]
# agent_rules = '<root>/_workroom/AGENTS.md'
```

外部の場所はすべて環境変数で差し替えられる。テストではすべて一時ディレクトリに向けること。

| 環境変数 | 用途 |
|---|---|
| `WORKROOM_CONFIG` | 設定ファイル |
| `WORKROOM_ROOT` | 作業ルート |
| `WORKROOM_STATE_DIR` | 使用履歴などの状態 |
| `WORKROOM_CLAUDE_DIR`（なければ `CLAUDE_CONFIG_DIR`） | Claude Code のデータ（既定 `~/.claude`） |
